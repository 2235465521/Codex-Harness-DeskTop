# ADR 0002: 文档多模态与数学公式引擎 (Rich Document Pipeline: Images & Math Formulas)

## 状态
已采纳 (Accepted) · 2026-09-14

## 背景与痛点
1. **学术与工业文档公式丢失**：学术论文、规范文档与技术方案（.docx / .pdf）重度依赖数学公式。此前系统仅抓取 Word OpenXML 的 `<w:t>` 纯文本，直接丢失了全部 Office 数学标记语言（OMML，`<m:oMath>`），导致核心公式缺失。
2. **文档图片与图表脱节**：.docx 内置的架构图、实验数据图与流程图无法在客户端右侧面板直观预览；大模型亦无法获得文档中的视觉线索。
3. **Token 成本与模型过载风险**：若无脑将文档中所有提取的图片一次性 Base64 塞给大模型，会导致上下文窗口剧烈膨胀、推理费用飙升且容易引发 LLM 注意力漂移。
4. **PDF 仅文本层提取**：此前仅抽取文字层，扫描件或排版复杂的 PDF 无法在工作台内进行可视化的平滑阅读。

## 架构决策 (Decisions)

### 1. 主进程零依赖 OMML 转译与富文档解构 (Zero-Dependency OMML Parser)
- **纯原生递归转译**：主进程内实现纯 JS 递归解析器 `ommlToLatex`，将 `<m:f>`（分数）、`<m:sSup>`/`<m:sSub>`（上下标）、`<m:rad>`（根号）、`<m:nary>`（求和/积分）、`<m:d>`（矩阵与定界括号）转译为标准 LaTeX。
- **引用保留公式**：优化 `extractDocxPlainText`，当用户在输入框通过 `@file.docx` 引用文档时，公式自动转为标准 `$...$` 与 `$$...$$`，使模型拥有完整数学语境。
- **解包关系映射**：解构 `word/_rels/document.xml.rels` 与 `word/media/`，抽取出图片并映射至段落流。

### 2. 轻量原生混合渲染与 KaTeX 引擎 (Native DOM + KaTeX)
- **文档端到端渲染**：针对 Word，前端基于结构化 Block 序列直接利用原生 React DOM 呈现标题、段落、公式与表格，辅以深色/浅色高对比度排版。
- **KaTeX 高性能渲染**：引入 `katex` 库并封装 `renderLatex`，兼具毫秒级排版速度与极小包体积；同时打通 `MarkdownRenderer.tsx`，对话气泡中大模型输出的 LaTeX 公式同样实时渲染。
- **PDF 连续平滑画布**：利用已打包的 `pdfjs-dist`，在右侧面板提供纵向平滑滚动 Canvas 视图，支持缩放与自适应宽度。

### 3. 按需一键引图入会话 (On-Demand Multimodal Injection)
- **面板 100% 呈现**：文档内的所有图片均在阅读面板中如实还原。
- **双模态操作条**：鼠标悬停于文档图片时，浮现「🔍 查看大图」与「➕ 引用至会话」：
  - 「查看大图」唤起高对比度 Lightbox 弹窗进行细节审阅；
  - 「引用至会话」将图片以 Data URI 形式挂载至输入框附件托盘，用户配合提示词主动发送给多模态模型，彻底杜绝 Token 爆炸。

### 4. 侧栏视图三态平滑切换 (Three-State View Transitions)
- 右侧面板导航栏提供「📖 阅读视图」、「📝 源码」与「📊 差异」切换胶囊；
- 打开 .docx 或 .pdf 时智能默认切至「📖 阅读视图」，同时允许随时切换至源码/Diff 查看底层结构或历史备份。

## 影响与收益 (Consequences)
- **多模态与工程结合**：在不依赖外部重量级工具（Pandoc、LibreOffice 或 Python 服务）的前提下，实现零延迟离线阅读工业文档。
- **安全沙箱无缝衔接**：所有文档与媒体读取严格受限于 Seam 17 权威沙箱（Containment 物理路径检验与权限阻断），绝无软链接逃逸风险。
